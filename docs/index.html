02 / EXECUTION MODEL

一批渲染，五个确定步骤

字段路径解析和数据准备各司其职：先得到完整路径，再由注册表按根路由并按 Provider 批量取值。

  1. 01

    RenderService

    解析模板并提取完整字段路径；语法错误在这里结束。

  2. 02

    字段路径

    保留如 station.name 的完整路径，局部变量不进入 Provider 请求。

  3. 03

    Registry 路由

    用路径根映射 Provider；未执行分支中的字段路径仍属于本批请求。

  4. 04

    Provider 批量

    按实际 Provider ID 合并字段，每个 Provider 每批只调用一次 ResolveAsync。

  5. 05

    策略与缓存

    应用字段策略和模板缓存，创建独立上下文，最终 HTML 编码输出。

↳注意：字段路径在渲染前确定；Provider 取值按本批实际路由合并，不按模板分支重复调用。

      04 / CONTRACT
      
            
      把边界留在正确的位置
      
          
      
          
      这些约定让模板解析、字段路由、Provider 批量取值和结果策略可以分别测试，也让一次批量渲染容易复盘。
      
        
      
        
      
          
      parse字段路径先行先解析模板并得到完整字段路径，不在语法错误时加载 Provider。
      
          
      route根映射 Provider注册表按路径根确定 Provider，成员路径保留给字段解析。
      
          
      load按 Provider 合并同一批按实际 Provider ID 合并并调用一次 ResolveAsync。
      
          
      policy策略与缓存按配置处理字段结果并复用模板/计划缓存，批次上下文彼此独立。
      
          
      warning缺值可降级sky 缺值时可输出 unreported，同时保留 MissingValue warning。
      
          
      errors稳定错误码未知字段路径返回 UnknownField，模板解析失败返回 InvalidTemplate。
      
          
      render统一 HTML 编码用本批结果创建上下文，渲染后编码插值输出。
