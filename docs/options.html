01 / START HERE

先分清三种配置

Demo 启动时从仓库根 appsettings.json 读取 RenderEngineOptions，再用它组装字段注册表、Provider 注册表和模板计划缓存。修改 JSON 后直接执行 dotnet run 即可观察效果；本页示例就是同一份配置形状。

A

TemplateCache

缓存已经解析并编译的 Liquid 计划。它复用模板结构，不缓存某一次请求的数据。

B

Fields / Groups

把模板中的根或完整路径映射到 Provider，并为每个字段确定上下文要求、值形态和失败动作。

C

Provider

按 Provider ID 批量解析已登记字段。Provider 负责把 SourceField 从数据源取出并返回结果。

运行顺序TryParse → Fluid AstVisitor 收集外部根（排除循环变量和 assign 局部变量）→ 注册表按根加载，同一根每轮最多一次 → 新建 TemplateContext 并 RenderAsync → HTML 编码输出。它是渲染前的静态依赖分析，所以未执行的 if 分支中引用的根也会被加载。

02 / TEMPLATE PLAN CACHE

TemplateCache：只缓存计划

TemplatePlanCache 使用独立的内存缓存，以模板文本为键。首次编译后计算计划大小；超过预算的单项不会写入缓存。缓存命中不会替代本轮数据解析。

选项默认值约束 / 行为
Enabledtruetrue 启用计划缓存；false 每次直接编译，不读取或写入缓存。
SizeLimitMiB16缓存总大小，按 MiB 转为字节预算；必须在 MinSizeLimitMiB 与 MaxSizeLimitMiB（含边界）之间。
MinSizeLimitMiB1允许的最小缓存预算，必须大于 0。
MaxSizeLimitMiB1024允许的最大缓存预算，必须大于或等于 MinSizeLimitMiB。
ExpirationMinutes30每个缓存项的绝对过期时间，允许 1..1440 分钟；不是滑动过期。
预算边界SizeLimitMiB 小于最小值或大于最大值，启动构造缓存时会抛出选项验证异常。每个计划若估算大小超过总预算，也会只编译、不缓存。
缓存对象缓存的是解析后的 TemplatePlan，包括编译模板和占位路径；请求上下文、Provider 返回值和最终 HTML 仍按轮次处理。

03 / FIELD REGISTRY

Fields、Groups、Members

InMemoryFieldRegistry 在构造时把配置变成不可变的字段定义。顶层 Fields 适合单个已知字段；Groups 适合共享 Provider 和策略的一组路径。

FIELDS完整键：label

显式顶层字段

键必须是非空、已去除首尾空白且不超过 128 个字符的根名，不能在 Fields 中直接写点号路径。

"label": {
  "ProviderId": "station-http",
  "SourceField": "label"
}
GROUPS根：station

共享组默认值

Groups 为成员提供共同的 ProviderId、RequiredContext、结构化值和失败策略。

"station": {
  "ProviderId": "stationProvider",
  "RequiredContext": ["stationId"],
  "AllowUnlistedMembers": true
}
MEMBERS完整键：station.name

成员覆盖

Members 显式声明成员；成员只覆盖自己指定的属性，其余属性从组继承。SourceField 默认是成员名。

"Members": {
  "name": { "SourceField": "stationName" }
}
INHERITANCE组默认 → 成员覆盖 → 最终 FieldDefinition
组ProviderId = stationProviderRequiredContext = [stationId]AllowStructuredValues = true
↓
station.nameSourceField = stationName其余属性继续继承
AllowUnlistedMembers设为 true 时，合法的 root.member 请求可以从组默认定义推断出来；推断成员的 SourceField 就是成员部分。它只允许组根名，不允许带点号的组键。

04 / FIELD POLICY

值、上下文与失败动作

字段先通过上下文检查，再由 Provider 返回结果，最后由 FieldPolicyEvaluator 按状态选择动作。动作名称统一是 Error、Empty、DefaultValue。

状态配置项ErrorEmptyDefaultValue
MissingValueOnMissingValue该字段报错，停止本项 HTML 渲染值为 ""，保留 warning使用 DefaultValue，保留 warning
InvalidContextOnInvalidContext必需上下文缺失或空白，报错输出空字符串，保留 warning使用默认值，保留 warning
ProviderErrorOnProviderErrorProvider 失败，报错输出空字符串，保留 warning使用默认值，保留 warning
AccessDenied固定处理始终是错误；不会被三个可配置的动作降级。

RequiredContext

字段或组声明必须存在且非空白的上下文字段，例如 ["stationId"]。检查失败不会调用对应 Provider，而是进入 OnInvalidContext。

SourceField

是 Provider 从数据源读取的字段名，不是模板中的 Liquid 路径。显式字段必须提供它；组成员不写时默认取成员名。

DefaultValue

只有选中的动作是 DefaultValue 时才会被使用；注册表会校验这时它不能为 null。它是文本回退值。

AllowStructuredValues

允许 Provider 返回 JSON 对象、数组、数字或布尔值供 Liquid 继续访问；关闭时 Provider 通常返回文本形式。

两个硬错误UnknownField 表示路径没有在注册表中找到，发生在 Provider 调用之前；AccessDenied 表示数据源拒绝访问，评估器固定返回错误。这两者都不是模板过滤器可以挽救的普通缺值。

05 / EMPTY VALUES

普通值与结构化值，判空不同

06 / WORKING CONFIG

一份短配置，直接可读

这是和当前 Demo 结构一致的最小示意。保存到仓库根 appsettings.json 的 RenderEngineOptions 节后，执行 dotnet run；Demo 会真实读取该文件，不会自动读取本页代码块。

{
  "RenderEngineOptions": {
    "TemplateCache": {
      "Enabled": true,
      "SizeLimitMiB": 16,
      "ExpirationMinutes": 30
    },
    "Groups": {
      "station": {
        "ProviderId": "stationProvider",
        "RequiredContext": ["stationId"],
        "AllowUnlistedMembers": true,
        "Members": {
          "name": { "SourceField": "stationName" }
        }
      }
    },
    "Fields": {
      "products": {
        "ProviderId": "station-http",
        "SourceField": "products",
        "AllowStructuredValues": true
      },
      "sky": {
        "ProviderId": "station-http",
        "SourceField": "sky",
        "OnMissingValue": "DefaultValue",
        "DefaultValue": "unreported"
      }
    }
  }
}

07 / DATA TO HTML

数据、模板、输出，逐格对照

下面的字段 products 允许结构化值。模板拿到数组后逐项渲染；不存在的 id 由 Liquid 的 default 过滤器兜底。

DATAProvider 返回
{
  "products": [
    { "id": "OPT-01" },
    { "name": "prism" }
  ]
}
TEMPLATELiquid
{% for product in products %}
[{{ product.id | default: 'N/A' }}]
{% endfor %}
OUTPUTHTML encoded
[OPT-01]
[N/A]
根失败先于过滤器如果 products 所属根的 Provider 返回 Error，字段评估已经产生错误，渲染不会继续；所以 {{ product.id | default: 'N/A' }} 根本没有执行机会。default 只处理已经进入 Liquid 的值，不会把 Provider 错误变成数据。

08 / EXTEND SAFELY

自定义字段与 Provider

扩展点保持窄而明确：字段配置描述契约，Provider 实现取数。这样模板不需要知道 HTTP、JSON 或缓存细节。

01

加字段定义

在 Fields 或 Groups.Members 增加模板键，设置 ProviderId、SourceField 和必要策略。

02

实现数据源

新增实现 IDataProvider 的类，提供唯一 Id，在 ResolveAsync 中按字段批量返回 FieldValue。

03

注册 Provider

把实现放入 ProviderRegistry 使用的 Provider 集合；配置中的 ProviderId 必须与 Id 精确一致。

04

验证边界

用真实模板检查缺上下文、空白值、结构化值、Provider 错误和 HTML 特殊字符的输出，再看首页的运行案例。
